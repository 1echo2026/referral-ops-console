# 转介绍数据看板 · 运营中台

一个零依赖的本地数据中台：**上传底表 → 配置取数逻辑 → 匹配销售架构 → 出看板**。
后台面向数据运营，前台面向各基地负责人，权限与数据范围自动隔离。

---

## 启动

```bash
# 方式一：双击 start.bat（Windows，会自动打开浏览器）
# 方式二：
node server.js
```

打开 <http://localhost:5600>（`/admin` 管理后台，`/dashboard` 基地看板）。

首次启动会根据 `seed.js` 生成一份演示数据到 `data/db.json`（6 个基地 / 37 人架构 / 4 类底表 / 204 条目标）。
想恢复初始数据：`npm run reset` 后重启。

## 四个核心板块

### ① 账号与权限（`/admin#accounts`）
- 账号统一在后台配置，分两类：**后台管理员**、**基地查看**。
- 基地账号必须绑定基地，接口层强制 `baseId`，无法越权查看其他基地。
- 支持新建 / 编辑 / 停用 / 删除 / 重置密码（新密码只显示一次）。
- 页面附带权限矩阵与基地覆盖检查（哪个基地还没配账号）。

### ② 数据底表 + 取数逻辑（`/admin#datasets`）
每类数据一个入口，点开后有 3 个页签：

| 页签 | 作用 |
| --- | --- |
| 底表上传 | 拖拽 xlsx / xls / csv，自动按列名匹配标准字段，预览后写入（可替换或追加） |
| 字段映射与取数逻辑 | 把底表列映射到标准字段；定义「指标口径」：计数 / 去重计数 / 求和 / 平均 / 组合公式，可加过滤条件；写明口径说明 |
| 取数预览 | 用当前配置跑一遍全量数据，立刻看到按基地、按高经的结果，验证口径对不对 |

关键点：**上传之后不直接出图**，而是由「取数逻辑」把底表整理成指标。改映射或改口径保存后立即重算，不用重新上传。

### ③ 销售架构 + 业绩目标（`/admin#org`、`/admin#targets`）
- 架构表把**一线工号**映射到高经 / 团队 / 基地。
- 匹配规则：取「生效日期 ≤ 记录日期」的最新一条 → 调组后历史数据仍归旧团队，新数据自动归新团队（演示数据里 `E1004` 在 9/1 转组，可验证）。
- 目标按「期间 + 层级（基地/高经）+ 指标」维护，重复上传自动覆盖；看板达成率 = 取数结果 ÷ 目标。

### ④ 整体数据看板（`/admin#analytics`）
- 可切数据类别、基地、高经、时间范围；每个指标都带目标与达成率。
- 图表：趋势（按月的两个指标）、状态/渠道分布、基地对比、目标达成排行。
- 架构下钻：高经 → 团队 → 工号，点开高经行展开成员。
- 支持导出当前维度 CSV。

## 前台基地看板（`/dashboard`）

- 基地账号只看到本基地数据；**标「全国」的指标**（如转化率）展示全体基地口径 —— 各指标是否对外展示全体数据，在「取数逻辑 → 指标 → 展示范围」里配置。
- 顶部可按高经 / 团队切换，下方所有图表、目标达成、下钻表格随之变化。
- 管理员访问时可切换基地，作为发布前预览。

## 取数逻辑怎么算

指标定义示例（`新用户直推未转化` 数据集）：

| 指标 | 定义 |
| --- | --- |
| 线索量 | `count` 全部行，过滤 `跟进状态 ≠ 无效号码` |
| 客户数 | `distinct` 手机号，同样过滤 |
| 转化数 | `count`，过滤 `跟进状态 = 已转化` |
| 转化率 | `ratio`，公式 `conv / list` |

引擎每一步都可追溯：原始行 → 按 `mapping` 取标准字段 → 按 `工号 + 日期` 取架构 → 过滤 / 聚合 → 按基地 / 高经 / 团队 / 月份分组。

## 接入真实数据

1. 删掉 `data/db.json` 并用 `npm run reset`，或在后台逐类上传自己的底表。
2. 先传「销售架构」，保证工号能匹配上高经；否则看板右上角会提示「未匹配架构 N 行」。
3. 再逐类上传底表 → 检查「取数预览」的数字 → 调整映射或口径。
4. 最后在「账号与权限」里给每个基地建账号。

数据存放在 `data/db.json`，直接备份这个文件即可。
